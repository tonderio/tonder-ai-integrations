# Tonder Web SDK 0.1.16

A documentation sync. The plugin's code is unchanged; what changed is what the bundled docs tell an agent to generate, and three of those corrections fix integrations that would have been wrong.

## Corrected guidance

- **`locale` mapped to a CSS property that does not exist.** The docs described `-apple-pay-button-locale`, by analogy with the real `-apple-pay-button-type` and `-apple-pay-button-style`. Apple localizes the button from the `lang` attribute or `-webkit-locale`. WebKit drops unknown declarations silently, so an agent following the old docs produced an English button, no warning, and nothing to search for.
- **`type` was missing seven of Apple's values.** The union listed 9; Apple defines 16 across API versions. `add-money`, `contribute`, `reload`, `rent`, `support`, `tip`, and `top-up` are now available.
- **The domain-verification file no longer carries a filename in the docs.** It is described as the path plus the file Tonder sends. Naming one is the failure: Apple fetches the exact name that was registered, so a merchant who renames to match the docs gets a 404 and a failed verification with nothing pointing at the cause.

## Added

- `width` on `customization.apple_pay_button`. Apple permits resizing and the SDK now exposes it, so a full-width Apple Pay button no longer needs merchant CSS reaching into the SDK's own stylesheet.
- The Apple Pay recipe shows `customization.apple_pay_button` in full, with every value inline. It referenced the field without demonstrating its shape.
- `SECURE_TOKEN_REQUIRED` in `pay()`'s throws table, and a quick-start note that a plain card payment needs a secure token when Card on File is enabled for the business. That is an account setting rather than something in the integration, so the same generated code works for one merchant and fails for another.
