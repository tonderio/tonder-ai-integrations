# Tonder Web SDK 0.1.23

A documentation sync to Web SDK `0.1.9`, plus three build-time advisory patches. The plugin's code is unchanged, and this time the bundled documentation is unchanged too.

## The sync carries no content change

Of the 32 files carried over from the `0.1.8` snapshot, **31 are byte-identical**. The only difference is `manifest.json`, which records the version and the generation timestamp. Nothing was added or removed, and the SDK README is identical at 107530 bytes.

That is stated as a measurement rather than an impression, and the distinction is the point. The `0.1.21` and `0.1.22` releases each had to correct a recipe, because recipes are hand-written, the sync does not touch them, and an SDK behaviour change leaves them describing the previous release with full confidence while nothing fails. The `0.1.22` entry recorded that checking by hand is the only thing that catches it.

Comparing every file in both snapshots answers the same question without depending on someone noticing. Here it returned nothing to correct.

## Patched

- `postcss` and `nanoid` in the MCP lock file.
- `vite` raised past the dev-server advisory in the `02-html-legacy-sdk` and `05-lite-legacy-react` example fixtures.

All three are build-time only. Neither reaches the shipped plugin payload.

## A gap worth naming

This file resumes a practice that lapsed. `docs/releases/` ran from `0.1.1` to `0.1.16` and then stopped, while `CHANGELOG.md` kept going — so `0.1.17` through `0.1.22` have changelog entries and no release notes. The release flow reads `docs/releases/<version>.md` as the `--notes-file` for the GitHub release, so each of those releases either shipped without notes or had them written somewhere that is not in this repository.
