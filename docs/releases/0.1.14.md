# Tonder Web SDK 0.1.14

Maintenance release. The plugin's content is unchanged; what changed is how a release is assembled, so that adding a second plugin costs data instead of script edits.

## Changed

- A plugin's version now lives in one place, `plugins[].version` in `.claude-plugin/marketplace.json`. `scripts/sync-web-sdk-skill.mjs` stamps it into the Claude manifest, the Codex manifest, and the Codex marketplace `source.ref`. Releasing edits one number and runs the sync a maintainer already runs; it used to mean editing five files by hand.
- The catalog's own `version` no longer mirrors a plugin's. It describes the catalog's shape and is bumped when a plugin is added, removed, or renamed. With several plugins on separate cadences, a catalog version tracking one of them is wrong for the rest.
- Packaging reads which skills each plugin bundles from `plugin-packaging.json`, keyed by the same plugin name the catalogs use, instead of naming one skill and two target directories. A declared skill that does not exist now fails the sync with a non-zero exit rather than shipping a plugin without it.

## Tests

- A version drift test fails when any derived version diverges from the catalog, naming the file and the mismatch. It closes a gap the existing tooling cannot see: `claude plugin tag` compares the Claude manifest against the catalog only, so a stale Codex `source.ref` passed validation while leaving Codex users on the previous release.
- A packaging test fails when a plugin's packaged skills or MCP payload are missing or drift from their source.

Both guards re-read the filesystem rather than importing the scripts they check. A guard that shares code with what it guards inherits its bugs and passes on a wrong-but-consistent result.
